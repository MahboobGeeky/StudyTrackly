# JavaScript migration log

StudyTrackly is now a JavaScript-only project. Editable source lives in `backend/src` and `frontend/src`. `dist` is Vite build output only (frontend). The backend runs `src/index.js` directly.

Interrupted work had already finished Phases 2–6 (TS deleted, Prisma/`dist` removed, Data Room ported, scripts/deps updated). This log records that work plus Phase 7–8 validation completed afterward.

## 9. Follow-up review (auth, MongoDB, leftover issues)

Inspected Mongoose models/routes, Google OAuth + JWT, and frontend `api()` integration. Did not redo the JS migration.

### Verified (no change)

- Database layer is MongoDB Atlas via Mongoose only (`connectDb` → `mongoose.connect(env.MONGO_URI)`).
- Auth: Google OAuth callback issues JWT `sub` = user id; `requireAuth` sets `req.userId`; frontend stores `studytrackly_token` and attaches `Authorization: Bearer`.
- `passwordHash` stays on the User schema for existing documents; login is Google-only. Removing the field would be a schema change, not a bugfix.
- `REDIS_URL` is read by `redis.js` (optional cache). `jsconfig.json` remains for `@/*` aliases.

### Genuine fixes

| Issue | Fix |
| --- | --- |
| OAuth callback ran `decodeURIComponent` on a value already decoded by `URLSearchParams`, which throws if a Google display name contains `%` | `JSON.parse(userRaw)` only |
| Deleting a course left sessions pointing at a missing course (`s.course` undefined → UI crash) | `Session.deleteMany` for that course; invalidate sessions + stats cache |
| Zod validation failures returned HTTP 500 | `errorHandler` maps `ZodError` to 400 |
| Sessions/Calendar assumed `s.course` always present | Optional chaining / `"Unknown"` fallback |
| Unused `isRedisEnabled` export | Removed |

### Still not a code bug

- Interactive Google consent in this environment still requires a real Google account.
- npm audit items were not auto-fixed (unrelated upgrades).
